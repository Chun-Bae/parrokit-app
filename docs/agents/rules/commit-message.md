# Commit Message Rules

- 커밋 메시지는 항상 `[+] {type}: {변경 대상} {동작}` 형식으로 작성한다.
- type은 `feat/fix/refactor/docs/test/chore/ci/build/perf/style/revert` 중 하나만 사용한다.
- 변경 요약은 한국어 명사형으로 작성한다.
- 변경 요약에는 실제 변경 대상과 수행 동작만 작성한다.
- 형용사, 부사, 평가 표현, 홍보성 표현, 감정 표현은 사용하지 않는다.
- 추상 표현만으로 요약하지 않는다.
- 내부 대화 맥락, 선택지 번호, 작업 지시 내용은 사용하지 않는다.
- 괄호, 이모지, 장문 설명은 사용하지 않는다.
- 한 커밋에 여러 성격의 변경이 있으면 각 줄마다 `[+] {type}: {변경 대상} {동작}` 형식으로 나누어 작성한다.
- 문서 변경이 포함되면 변경 대상에 문서명을 포함한다.
- build는 `[+] build: {버전} {대상} {동작}` 형식으로 쓴다.
- Co-Author 금지.

## 작성 단위

변경 요약은 아래 조합으로만 작성한다.

```text
{변경 대상} {동작}
```

## 허용 동작

- 추가
- 수정
- 삭제
- 분리
- 통합
- 이동
- 정리
- 반영
- 연결
- 적용
- 교체
- 갱신
- 제거

## 금지 방식

```text
명확화
체계화
고도화
최적화
안정화
개선
강화
완성
완벽 적용
효율 개선
사용성 개선
```

## 권장 예시

```text
[+] feat: 커뮤니티 알림 기능 추가
[+] fix: 알림 중복 저장 오류 수정
[+] refactor: 커뮤니티 provider 구조 분리
[+] docs: 커밋 메시지 규칙 수정
[+] chore: Firebase 설정 파일 갱신
```
