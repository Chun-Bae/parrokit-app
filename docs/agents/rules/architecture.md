# Architecture Guide

이 문서는 선택적인 참고 지침이다. 구조보다 요청한 기능의 동작과 변경 용이성을 우선한다.

- 기존 구조는 필요할 때 재사용하되 새 코드에 MVVM이나 Clean Architecture를 강제하지 않는다.
- 작은 화면은 한 파일에서 상태, UI, 간단한 동작을 함께 구현해도 된다.
- 반복되는 코드나 복잡한 동작이 실제로 생기면 위젯, 함수, 서비스 등 적절한 단위로 분리한다.
- 기능 하나를 위해 빈 레이어나 전달만 하는 Provider, UseCase, Repository를 만들지 않는다.
- 폴더와 파일 이동은 작업 목적에 필요한 범위에서만 진행한다.
- 기존 기능이나 저장 데이터에 영향이 큰 변경은 먼저 범위와 접근을 설명한다.
