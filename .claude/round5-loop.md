할 일 (위에서부터. 각 항목은 여러 반복에 나눠도 된다. 진행 상태는 round5-audit.md에 적는다)
1. 새 디자인 정리: 4차에서 스위치 뒤에 둔 화면(홈 무대 조작 줄, 오늘 목표 줄, 내 문장 기록 줄인 모양, 학습 허브 준비 중 줄, 콘텐츠 제작 첫 화면, TTS 소개 상자, Video 경고, 단어 탭 예시 안내)의 예전 갈래를 지운다. AppConfig.newDesign·newDesignListenable·prefs 'newDesign'·더보기 스위치를 없앤다. 예전 모양을 보던 테스트(stage_preview_test의 newDesign=false 등)는 새 모양 기준으로 고친다. 화면 하나씩 지우고 시뮬레이터로 확인한다
2. 문장 설정 창: '적용' 버튼을 없애고 체크를 바꾸면 바로 반영한다. 저장은 문장 탭의 '앵무새 끄기'(밀어서 동작)와 같은 설정(SentenceActivityStore의 루틴 표시)을 쓴다. 문장 탭과 홈 무대에 바로 보여야 한다. 테스트를 더한다
3. 질문 필터: '화제의 질문'은 불러온 질문을 좋아요 많은 순, '오래된 질문'은 오래된 순으로 앱에서 다시 정렬한다(서버 조회는 그대로, 인덱스 배포 없음). 테스트를 더한다
4. 커뮤니티 글쓰기 버튼: 질문 탭에서는 "질문하기"로 바로 질문 쓰기 화면을, 투표 탭에서는 바로 투표 만들기를 연다. 게시판 탭은 지금처럼. 실제 글은 쓰지 않는다(화면이 열리는 것까지만 확인)
5. 플레이어 "한 줄씩 멈춤": 자막 한 줄이 끝나면 자동으로 멈추는 토글을 플레이어 아래 알약 버튼 줄에 더한다. 켜고 끈 값은 기기에 기억한다. 재생 화면은 기기 클립이 있어야 보이므로, 시뮬레이터에 기기 저장 클립을 하나 만들어(짧은 영상, 저장 위치 '로컬') 확인한다. '구간/전체재생' 버튼을 두 칸 세그먼트로 바꾸는 것도 이때 함께 본다
6. 단어 탭을 실제 기능으로(문장 탭과 같은 구조). 큰 일이라 나눠서 한다
   - 먼저 조사: 단어장·어휘 앱(예: 단어 저장, 예문, 복습 간격, 뜻 자동 채우기)의 App Store 스크린샷·소개·디자인 글을 보고 design-research.md에 "8. 단어장" 표로 정리한다. 특정 앱의 생김새·브랜드·문구를 베끼지 않고 패턴만 가져온다
   - 구조: 문장 탭과 같게. 언어 고르기는 문장 탭의 드롭다운(LearningLanguagePicker), 카테고리 칩, 내 단어 목록은 테두리 없는 줄 + 밀어서 동작(SwipeActionTile), 단어 상세, 단어 추가. "둘러보기"는 만들지 않는다(예시 둘러보기·내 단어/둘러보기 전환 없앰). 예시 데이터와 "예시 화면이에요" 안내를 없앤다
   - 단어 넣기: 직접 입력(단어, 뜻, 예문 선택) + 문장 상세에서 단어를 골라 저장(원래 문장과 연결). 뜻 채우기는 문장의 '뜻·발음 채우기'처럼 이미 있는 서버 호출을 쓸 수 있으면 쓰고, 새 서버 함수가 필요하면 배포 필요 목록에 적는다
   - 복습: "오늘 다시 볼 단어"를 실제로 계산한다(문장 활동 기록처럼 마지막 복습일·간격). '시작'을 누르면 예문을 보고 말하는 짧은 복습 화면
   - 저장: 문장(MySentenceStore)과 같은 방식. 게스트는 기기(SharedPreferences 키 parrokit.my_words.v1.{accountId}), 로그인은 Firestore. 문장 클라우드 저장과 같은 모양의 컬렉션을 쓰고 firestore.rules에 규칙을 추가한다(본인만 읽고 쓰기, 필드 검증). 규칙 배포는 하지 않는다 → round5-audit.md "배포 필요"에 명령 한 줄과 함께 적는다. 배포 전에는 로그인 상태에서 저장이 실패할 수 있으니, 실패하면 기기에 남기고 안내하는 처리를 넣는다
   - 테스트: 저장소(게스트/로그인 가짜), 복습 계산, 화면(추가·삭제·밀기)을 위젯 테스트로
7. 기존 UX 계속 개편: 4차에서 안 본 화면을 하나씩 사용성 점검하고 4차 원칙으로 고친다. 후보: 커뮤니티 글 상세·댓글, 알림, 검색, 프로필 편집, 클립 상세·구간 목록, 문장 상세, 온보딩·로그인 화면(코드와 화면 보기만, 로그인 시도 금지), 환전·광고 보상 시트, 도움말. round4-audit.md의 "발견" 항목(단어 탭 다크 언어 버튼 대비, 콘텐츠 제작에서 나가면 홈으로 가는 것 등)도 처리한다
8. 테스트 보강: 바꾼 로직마다 테스트를 더한다. 할 일이 떨어지면 테스트가 없는 중요한 로직(지갑 표시, 클립 저장 흐름, 커뮤니티 필터, 라우팅)에 테스트를 더한다

확인용 데이터
- 커뮤니티 질문·투표 화면을 보려면 개발 빌드에서만 켜지는 가짜 글을 쓴다. kDebugMode일 때만 동작하고 출시 빌드에는 들어가지 않게 한다(예: --dart-define=PK_FAKE_COMMUNITY=true 로 켤 때만 CommunityProvider가 가짜 목록을 돌려준다). 기본은 꺼짐. 가짜 글에서 공감·댓글·투표를 눌러도 서버로 가지 않게 막는다
- 시뮬레이터 앱의 문장·단어·클립 등 로컬 데이터는 추가·삭제해도 된다. 커뮤니티는 실제 출시 중이라 글쓰기·공감·투표·댓글·신고를 실제로 하지 않는다
- 실제 서버에 쓰는 것은 커뮤니티가 아니어도 꼭 필요할 때만 하고 진행 기록에 적는다
