# 6차 — 출시 점검 (항상 최신)

시작: 2026-11-25 밤. 30분마다 예약된 세션 루프. 지시는 `.claude/round6-loop.md`.

5차(반복 505, 2026-11-18에서 멈춤)는 화면 다듬기였다. 6차는 돈·데이터 유실·심사·보안·
배포 어긋남만 본다. 글귀와 여백은 보지 않는다.

**앱은 이미 App Store에 나가 있다**(무료, [id6751800510](https://apps.apple.com/kr/app/id6751800510),
업데이트 기록 있음). 안 나간 것은 **유료 구독 층**이다. 그래서 급한 순서가 둘로 갈린다.

- **이미 쓰고 있는 사람을 다치게 하는 것** — 데이터가 사라지거나 앱이 깨지는 것.
  내일 고쳐도 되는 일이 아니다. 지금 당장 누군가 겪고 있을 수 있다
- **유료를 켜기 전에 끝내야 하는 것** — 상품 등록, 사업자 정보, 결제 대사

11-25에 이것을 "출시 전 점검"으로 잘못 적었다. 앱이 안 나간 줄 알고 썼다.

## 막고 있는 것 (위부터 급하다)

### 1. 이미 나간 앱에서 사용자를 다치게 하는 것

11-25 하루에만 데이터 유실 결함이 둘 나왔다. **같은 모양이 더 있는지 보는 것이 6차의 첫 일이다.**

- `initUserDocument`가 merge set이라 네트워크가 잠깐 끊긴 것도 '문서 없음'으로 보고
  `parrots`·차단 목록·`fcmTokens`를 날렸다 (고침, 미배포 아님 — 앱 코드)
- 탈퇴가 중간에 실패하면 문서는 없고 계정은 살아 있었다 (고침, 배포 완료)

둘 다 **쓰고 있는 사람이 이미 겪었을 수 있다.** 비슷한 자리를 찾는다:
`catch (_)`로 실패를 삼키고 넘어가는 쓰기, merge로 덮어쓰는 기본값, 순서가 뒤집히면
반쪽이 남는 여러 단계 작업.

### 2. 유료를 켜기 전에 끝내야 하는 것 — 사용자가 할 일

- **ASC 구독 상품 8개가 없다.** `com.bull.parrokit.sub_{light,plus,pro,max}_{monthly,yearly}`가
  전부 Missing Metadata다. 앱 자체는 이미 나가 있으니 심사와는 상관없고, **구독을 팔 수 없을
  뿐이다.** 지금 앱은 RevenueCat 페이월 대신 자체 미리보기 시트("아직 구독 상품을 준비하는
  중이에요")를 띄운다
- **약관·방침에 사업자 정보가 없다.** 운영자 표기가 "Parrokit 운영자" + Gmail뿐이다.
  상호·대표자·사업자등록번호·주소·통신판매업 신고번호가 없고 개인정보 보호책임자도 실명이
  아니다. 무료로 내고 있는 지금은 넘어가도, **인앱결제로 돈을 받는 순간 전자상거래법 표시
  의무**가 걸린다. 기억에 '예비창업패키지 때문에 사업자등록을 미룬다'가 있는데, 그 판단은
  무료일 때만 성립한다. **유료로 갈지부터 사용자가 정해야 한다**
- **약관 시행일이 2026-12-01이다.** 두 문서 머리에 "2026년 12월 1일부터 적용됩니다"가 있다.
  유료 전환을 그 전에 하면 아직 시행 안 된 약관으로 돈을 받는 셈이다

### 3. 업데이트 심사에서 걸릴 수 있는 것

- **UGC 콘텐츠 필터가 없다.** 신고(`community_report_actions.dart`)와
  차단(`block_user_usecase.dart`)은 있는데, 애플 1.2는 **거르는 수단**을 따로 요구한다.
  `functions/src/`에 금칙어를 거르는 코드가 없고 글이 그대로 올라간다.
  - 다만 **이미 통과해서 나가 있다.** 반드시 걸린다고는 할 수 없고, 다음 업데이트에서
    지적되면 그때 막힌다는 정도로 본다. 서버에 게시글 생성 트리거 하나면 된다
  - 정정(11-25): 결제 화면의 약관·개인정보 링크는 **있다.** Flutter 소스에 없어서 없다고
    적었다가 RevenueCat 페이월을 직접 열어 확인했다 — 두 페이월 모두 아래에
    "이용 약관 · 개인정보 처리방침 · 구매 복원"이 있다

### 4. 돈이 새거나 신뢰를 잃는 것

- **결제 대사(reconcile)가 없다.** RevenueCat 웹훅이 안 오면 — 장애든, URL 오타든, 그 순간
  함수가 죽었든 — 사용자는 **돈을 냈는데 패롯이 안 들어온다.** 알아챌 방법도, 나중에 메울
  방법도 없다. 문의 창구는 Gmail 하나뿐이다. **신뢰는 여기서 가장 빨리 무너진다**
- **웹훅 실패 알림이 없다.** 돈이 샜는지 알 길이 없다

### 5. 서버와 저장소가 어긋나 있다

5차 '배포 필요'에서 넘어온 것. **아직 확인 안 했다 — 6차 첫 일거리로 확인한다.**
오늘(11-25) 배포한 것은 `deleteAccount` 하나와 `firestore.rules`뿐이다.

- 서버 안내 말투 16곳(`6d302cc7`), 커뮤니티 알림 글귀(`465da9de`),
  알림 설정 반영(`4bd8a2ea`), `checkStorageQuota`(`93f105d1`),
  모델 교체 둘(`c347a629`, `dbc34531` — 종료된 모델을 부를 가능성)
- 한 번에 나간다: `npx -y firebase-tools@latest deploy --only functions --project parrokit-45126`

### 6. 켜야 하지만 아직 못 켜는 것

- **App Check이 꺼져 있다**(`functions/src/appCheck.ts`의 `ENFORCE_APP_CHECK = false`).
  앱에는 11-25에 넣었다(`firebase_app_check 0.4.9`). 순서상 **그 버전이 퍼진 뒤에만** 켤 수 있다.
  Firebase 콘솔의 App Check 모니터링에서 올바른 토큰 비율이 올라간 것을 보고 켠다.
  - 위험은 생각보다 작다: 비싼 호출이 전부 패롯으로 막혀 있고(`captionCost` → `applyLedger`),
    `firestore.rules`가 앱의 `parrots`·`crackers`·`subscription` 쓰기를 막고,
    익명 로그인이 없어 계정을 만들려면 진짜 이메일이 필요하다
  - 콘솔에서 iOS(App Attest/DeviceCheck)·Android(Play Integrity) 등록은 사용자가 해야 한다
- **R2 API 토큰을 아직 안 바꿨다.** 원래 값이 채팅에 한 번 노출됐다

### 7. 고쳤지만 아직 안 끝난 것

- **오류 로그 35곳이 Crashlytics에 안 간다.** `debugPrint`는 안 올라간다.
  11개 파일 35곳이 남았고 챗봇이 19곳으로 가장 많다. 출시하면 무엇이 깨지는지 못 본다

### 6차 직전(11-25)에 한 것 — 5차 파일에는 안 적혔다

- **탈퇴를 서버가 끝까지 한다**(`3965cfab`, 배포됨). 앱이 ①문서 → ②Auth 순으로 지워서

  새 콜러블 `deleteAccount`가 Admin SDK로 닉네임 → 문서·하위 컬렉션 → **Auth 맨 마지막** 순으로
  지운다. 중간에 끊겨도 계정이 남아 다시 부르면 이어서 끝낸다. 재로그인 가드는 지웠다
- **App Check을 앱에 넣었다**(`46f1e49b`). 서버 스위치는 false 그대로
- **`initUserDocument`가 있는 문서를 건드리지 않는다**. merge set이라 네트워크가 잠깐 끊긴 것도
  '문서 없음'으로 보고 `parrots`·차단 목록·`fcmTokens`를 날렸다
- **`firestore.rules`에서 서버 전용 칸을 막았다**(배포됨)
- **문장·단어 불러오기가 엉뚱한 파일을 가린다**(커밋 전). 못 읽는 세 갈래가 모두 `(0,0)`을
  돌려줘서 중복 파일과 똑같이 "새로 들어온 문장과 단어는 없어요."가 떴다
- **백업 불러오기가 0개일 때도 말한다**(커밋 전)
- 앱 아이콘·스플래시·로그인 로고를 새 그림으로 바꿨다(커밋 전). 페이월 둘은 RevenueCat에

## 안건 (사용자가 정할 것)

- **유료로 낼지, 무료로 먼저 낼지.** 사업자등록과 묶인 문제다. 무료면 구독·충전을 숨기고
  내면 되고, 유료면 사업자 정보가 먼저다
- **지급을 서버로 옮길지**(5차 505에서 넘어옴): 크래커 잔액을 앱이 자기 문서에 쓸 수 있다.
  앱을 지우면 상한이 풀린다. `grantPracticeReward`를 함수로 옮기고 장부를 사용자 문서
  아래에 둬야 제대로 막힌다
  - 참고: `parrots`·`crackers`는 11-25 규칙 배포로 앱 쓰기가 막혔다. 이 안건이 아직
    유효한지 **다시 확인해야 한다**
