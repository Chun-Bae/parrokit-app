# UI 방향 결정 기록

밤새 돌린 작업에서 내가 직접 정한 UI 패턴 방향과 그 이유. 아침에 읽고
마음에 안 드는 결정은 해당 커밋만 되돌리면 된다.

각 항목은 커밋 하나에 대응한다.

시작: 2026-11-12

---

## 1. 둥지 그림 바닥 그림자를 밝기 대응시킴

**화면:** 홈 (dashboard), 학습 화면 (stage preview)

**문제:** 앵무새가 서 있는 바닥 그림자 타원 두 개가 고정 색이었다.
`0xFFE4EDF2`(바깥)와 `0xFFF8FCFE`(안쪽). 라이트 모드의 옅은 배경 위에서는
부드러운 바닥으로 읽히지만, 다크 모드에서는 검은 배경 한가운데 흰 덩어리로
떠 보인다.

**고른 방향:** 새 팔레트 클래스를 만들지 않고 `HomeTokens`에 `groundOuter` /
`groundInner`를 추가했다. 홈 일러스트 색을 담는 토큰이 이미 그것이고,
`garden`과 `mastery`처럼 그림에 쓰는 색이 이미 거기 들어 있다.

| | 라이트 | 다크 |
|---|---|---|
| `groundOuter` | `0xFFE4EDF2` (그대로) | `0xFF1B2533` |
| `groundInner` | `0xFFF8FCFE` (그대로) | `0xFF243246` |

다크 값은 `HomeTokens.dark.surfaceSoft`(`0xFF1A2432`) 언저리로 잡아서
배경에서 살짝 떠 보이되 빛나지 않게 했다. **라이트 모드 값은 바꾸지 않았으므로
라이트 외형은 그대로다.**

**다른 방법을 안 고른 이유:** `CustomPainter`에 `isDark`를 넘겨서 그 안에서
색을 고르는 방법도 있었지만, 그러면 다크 값이 다시 그림 코드 안에 박힌다.
토큰으로 빼야 나중에 색을 바꿀 때 한 곳만 고친다.

**딸려온 변경:** `NestScenePainter`와 `_GrowthPainter`가 `BuildContext`가 없는
`CustomPainter`라 두 색을 생성자로 받게 했다. `shouldRepaint`에도 비교를 넣어
테마가 바뀌면 다시 그린다.

**되돌리려면:** 이 커밋만 revert 하면 된다.
