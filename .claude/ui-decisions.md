# UI 방향 결정 기록

밤새 돌린 작업에서 내가 직접 정한 UI 패턴 방향과 그 이유. 아침에 읽고
마음에 안 드는 결정은 해당 커밋만 되돌리면 된다.

각 항목은 커밋 하나에 대응한다.

시작: 2026-11-12

---

## 1. 둥지 그림 바닥 그림자를 밝기 대응시킴

**화면:** 홈 (dashboard), 학습 화면 (stage preview)

**문제:** 앵무새가 서 있는 바닥 그림자 타원 두 개가 고정 색이었다.
`0xFFE4EDF2`(바깥)와 `0xFFF8FCFE`(안쪽). 라이트 모드의 옅은 배경 위에서는
부드러운 바닥으로 읽히지만, 다크 모드에서는 검은 배경 한가운데 흰 덩어리로
떠 보인다.

**고른 방향:** 새 팔레트 클래스를 만들지 않고 `HomeTokens`에 `groundOuter` /
`groundInner`를 추가했다. 홈 일러스트 색을 담는 토큰이 이미 그것이고,
`garden`과 `mastery`처럼 그림에 쓰는 색이 이미 거기 들어 있다.

| | 라이트 | 다크 |
|---|---|---|
| `groundOuter` | `0xFFE4EDF2` (그대로) | `0xFF1B2533` |
| `groundInner` | `0xFFF8FCFE` (그대로) | `0xFF243246` |

다크 값은 `HomeTokens.dark.surfaceSoft`(`0xFF1A2432`) 언저리로 잡아서
배경에서 살짝 떠 보이되 빛나지 않게 했다. **라이트 모드 값은 바꾸지 않았으므로
라이트 외형은 그대로다.**

**다른 방법을 안 고른 이유:** `CustomPainter`에 `isDark`를 넘겨서 그 안에서
색을 고르는 방법도 있었지만, 그러면 다크 값이 다시 그림 코드 안에 박힌다.
토큰으로 빼야 나중에 색을 바꿀 때 한 곳만 고친다.

**딸려온 변경:** `NestScenePainter`와 `_GrowthPainter`가 `BuildContext`가 없는
`CustomPainter`라 두 색을 생성자로 받게 했다. `shouldRepaint`에도 비교를 넣어
테마가 바뀌면 다시 그린다.

**되돌리려면:** 이 커밋만 revert 하면 된다.

## 2. 반지름 리터럴 중 토큰과 값이 같은 것만 먼저 토큰으로

**범위:** 앱 전체 88개 파일

**문제:** `AppRadius`가 이미 있고 48개 파일이 쓰고 있는데, 화면 코드에는
`BorderRadius.circular(12)` 같은 생숫자가 292곳 남아 있었다. 쓰이는 값이 25종이다.
4, 8, 12, 16, 20, 24처럼 토큰에 있는 값과, 2, 6, 10, 18, 22, 30처럼 없는 값이 섞여 있다.

**고른 방향:** 이번에는 **값이 토큰과 정확히 일치하는 199곳만** 바꿨다.
`99`는 `full`(999)로 합쳤다. 어떤 크기에서도 완전히 둥근 모양이라 눈에 보이는 차이가 없다.

| 값 | 토큰 | 곳 |
|---|---|---|
| 4 | `AppRadius.xs` | 13 |
| 8 | `AppRadius.sm` | 21 |
| 12 | `AppRadius.md` | 56 |
| 16 | `AppRadius.lg` | 34 |
| 20 | `AppRadius.xl` | 45 |
| 24 | `AppRadius.xxl` | 16 |
| 999, 99 | `AppRadius.full` | 14 |

**외형 변화가 없다.** 값을 그대로 두고 이름만 붙인 것이다.

**아직 안 바꾼 93곳:** 2, 3, 5, 6, 7, 9, 10, 13, 14, 15, 17, 18, 22, 28, 30, 32, 40, 50.
이걸 토큰 눈금에 맞추려면 **모양이 바뀐다.** 18을 20으로 올리거나 13을 12로 내리는 식이다.
한꺼번에 바꾸면 아침에 뭐가 달라졌는지 가려내기 어려워서 따로 뺐다.
화면별로 돌면서 그 화면 맥락을 보고 판단한다.

**한 화면씩이 아니라 한 번에 한 이유:** 같은 기계적 치환을 19개 화면에 나눠 커밋하면
되돌릴 때 오히려 불편하다. 외형 변화가 0이라 한 덩어리로 묶어도 위험하지 않다.

**되돌리려면:** 이 커밋만 revert 하면 된다.

## 3. 2dp 반지름에 `AppRadius.xxs` / `track` 토큰 추가

**범위:** 15개 파일 18곳

**문제:** `circular(2)`가 18곳 있는데 `AppRadius`에 2가 없었다. 쓰는 자리를
전부 확인해보니 역할이 하나다. 진행 막대, 슬라이더 레일, 바텀시트 드래그 핸들,
파형 막대 — 전부 얇은 바의 끝을 살짝 둥글린 것이다.

**고른 방향:** 눈금에 2dp를 넣었다.

```dart
/// 초극소 (2dp) - 진행 막대, 슬라이더 레일, 시트 드래그 핸들 같은 얇은 바
static const double xxs = 2;

/// 얇은 바 (2dp) - 진행 막대와 드래그 핸들
static const double track = xxs;
```

쓰는 쪽은 의미가 드러나는 `AppRadius.track`을 쓴다. **값이 그대로라 외형 변화가 없다.**

**가까운 값으로 올리지 않은 이유:** 2를 `xs`(4)로 올리면 높이 4dp짜리 진행 막대가
완전한 알약 모양이 된다. 얇은 바는 끝만 살짝 둥근 게 맞고, 2dp는 그 역할에
실제로 쓰이는 값이라 눈금에 넣는 게 맞다고 봤다.

**딸려온 변경:** `storage_cache_management_screen.dart`의 중괄호 없는 `if` 한 곳을
고쳤다. 내가 건드린 파일이 아닌데 분석기에 걸려서 함께 고쳤다. 동작은 그대로다.

**되돌리려면:** 이 커밋만 revert 하면 된다.

## 4. 보관함 파스텔 색을 `CollectionTokens`로 빼고 다크 값을 넣음

**화면:** 보관함 (문장·클립·단어 전부)

**문제:** 다크 모드에서 **상단 배너 글자가 거의 안 읽힌다.** 배경은 고정 파스텔
(`0xFFDDEFEA` 민트)인데 제목은 테마 기본 글자색을 써서 다크에서 흰색이 된다.
연한 민트 위의 흰 글자다. 왼쪽 동그라미는 반대로 `colorScheme.surface`를 써서
다크에서 어두워진다. 배경만 라이트에 남고 그 위 요소가 전부 뒤집힌 꼴이다.

보관함 탭 카드(문장/클립/단어), 문장팩 카드, 단어 카드, 친밀도 최고 단계
금색 카드가 모두 같은 구조다.

**고른 방향:** `HomeTokens`와 같은 꼴로 `CollectionTokens` ThemeExtension을 만들고
`AppTheme.light` / `AppTheme.dark`에 등록했다. 값은 `CollectionColors`에 그대로 두고
(`AppColors`와 같은 역할) 토큰이 밝기에 맞는 쪽을 골라 준다.

| 토큰 | 라이트 | 다크 |
|---|---|---|
| `mint` | `DDEFEA` | `132623` |
| `sky` | `DCE9F8` | `14212F` |
| `cream` | `FFE8C7` | `2B2316` |
| `mintInk` | `42636A` | `9CC2C7` |
| `skyInk` | `3D5966` | `9BBBCC` |
| `creamInk` | `AA6B20` | `E0A85C` |
| `tintLabel` | `526977` | `A3B5C0` |
| `liked` | `FF768B` | `FF8FA1` |
| `voiceActive` | `6D9890` | `8FBDB3` |

**다크에서 파스텔을 어떻게 할지:** 같은 색조를 어둡게 깐 면으로 갔다.
`AppColors`가 이미 `successSoft`(`ECFDF5`) ↔ `successSoftDark`(`0D2818`)로
같은 방식을 쓰고 있어서 거기 맞췄다. 파스텔을 그대로 두고 글자만 어둡게 하는
방법도 있지만, 그러면 다크 화면에 밝은 판이 세 개 떠서 눈에 거슬린다.

**네 가지 잉크를 세 가지로 줄였다.** 전에 `tabIcon`/`packIcon`/`packLabel`/`creamIcon`
네 색이 "파스텔 위 아이콘·라벨"이라는 같은 역할인데 값이 달랐다. 이번에 역할을
다시 나눴다. 배경 색조마다 잉크 하나(`mintInk`/`skyInk`/`creamInk`)와,
설명 글자용 공통 `tintLabel` 하나다. 배너 아이콘이 탭마다 제 색조의 잉크를 쓴다.

**딸려온 변경:** `packs`가 `static const` 목록이라 context를 못 받아서
`packsOf(BuildContext)` 메서드로 바꿨다. 금색 카드의 `_goldBackground`도
context를 받게 했다.

**되돌리려면:** 이 커밋만 revert 하면 된다.

**라이트 모드도 조금 바뀐다.** 배너 제목이 기존 테마 기본 글자색(거의 검정)에서
색조 잉크(`42636A`)로 바뀐다. 배너가 배경·아이콘·제목이 한 덩어리로 읽히게
하려고 일부러 그렇게 했다. 민트 배경 위 대비는 약 5.5:1로 본문 기준 AA를 넘는다.
원래 검정 제목이 좋으면 이 커밋을 되돌리면 된다.

## 5. 학습 언어 고르기는 그대로 두고 안쪽 숫자만 정리

**화면:** 홈, 보관함, 문장 추가, 학습 화면 (`LearningLanguagePicker`를 쓰는 네 곳)

**처음 본 것:** 홈에서는 알약 칩, 보관함에서는 전체 너비 행이라 같은 컨트롤이
화면마다 다르게 보였다. 통일 대상으로 적어뒀다.

**확인하고 뒤집은 것:** 코드를 보니 **이미 공용 위젯 하나이고 여는 것도 바텀시트
하나다.** 두 생김새는 `compact` 플래그로 의도해서 나눈 변형이다. 좁은 자리
(홈 헤더)에서는 알약 칩, 설정 행처럼 놓이는 자리(보관함)에서는 전체 너비.
맥락이 다르니 생김새가 다른 게 맞다. **통일하지 않았다.**

드롭다운이냐 바텀시트냐는 이미 바텀시트로 정해져 있다. 검색창과 국기·원어 이름까지
있는 목록이라 드롭다운에 넣기엔 크다. 그대로 둔다.

**대신 한 것:** 위젯 안의 생숫자를 토큰으로 바꿨다.

- 트리거 여백 `10/14`, `9/12` → `AppSpacing.sm`(8) / `AppSpacing.md`(12)
- 시트 안 여백 `20`, `16`, `12`, `10`, `7`, `5` → `AppSpacing` 눈금
- 목록 항목 반지름 `15` → `AppRadius.lg`(16)
- 목록 항목 제목의 `const TextStyle` → `context.texts.bodyLarge`
- 시트 높이 비율 `0.48`에 `_listHeightRatio` 이름과 설명을 붙였다

**외형이 조금 바뀐다.** 눈금에 맞추느라 몇 군데가 1~2pt 좁아지고 목록 항목
반지름이 15에서 16이 된다. 눈으로 확인했다.

**드래그 핸들 바로 아래 `2`는 눈금으로 안 올렸다.** 거기만 핸들과의 간격이라
`xs`(4)로 올리면 떠 보인다. 숫자로 두고 이유를 주석에 적었다.

**되돌리려면:** 이 커밋만 revert 하면 된다.

## 6. 바텀시트를 `useRootNavigator: true` 하나로 통일

**범위:** 앱 전체 `showModalBottomSheet` 36곳

**문제:** 학습 언어 시트를 열었더니 **하단 탭바가 모달 위로 떠 있었다.**
스크림은 위쪽만 덮고 탭바만 밝게 남는다. 따라가 보니 띄우는 방식이 네 갈래였다.

| 방식 | 곳 |
|---|---|
| `useRootNavigator: true`만 | 4 |
| `hideNavBarWhile(...)`만 | 4 |
| 둘 다 | 2 |
| 아무것도 안 함 | 26 |

`app_shell.dart`의 주석도 틀려 있었다. "네비바가 iOS 네이티브 뷰라서 모달 시트가
덮지 못한다"고 적혀 있었는데 그냥 Flutter 위젯이다. 진짜 원인은 시트가 쉘 안쪽
내비게이터에 올라가서 쉘의 `bottomNavigationBar`보다 아래에 그려지는 것이다.

**고른 방향:** `useRootNavigator: true` 하나로 모았다.

- 전역 가변 상태(`navBarHiddenCount`)가 필요 없다. 호출하는 자리에서 끝난다
- 스크림이 탭바까지 덮는다. 모달이면 그게 맞다
- `hideNavBarWhile`은 탭바를 사라졌다 나타나게 해서 열고 닫을 때 깜빡인다

**지운 것:** `navBarHiddenCount`와 `hideNavBarWhile`, 그리고 쉘의
`ValueListenableBuilder` 한 겹. 아무도 안 쓰게 되어 지웠다.

**확인:** 문장 가져오기 진행 창이 중첩 내비게이터 동작에 기대는 테스트가 있어서
(`중첩된 내비게이터 안에서 가져와도 진행 창만 닫히고 화면은 남는다`)
바꾼 뒤 전체 테스트를 돌렸다. +188 전부 통과.

**되돌리려면:** 이 커밋만 revert 하면 된다.

## 7. 세그먼트 컨트롤 다섯 벌을 `AppSegmentedTabs` 하나로

**화면:** 보관함(문장·클립·단어 전환, 내 문장/둘러보기, 내 단어/둘러보기),
라이브러리(유형별/태그, 로컬/서버/클라우드)

**문제:** 같은 "둘·셋 중에 하나 고르기" 컨트롤이 **다섯 벌 따로 만들어져 있었고
시각 언어도 둘로 갈렸다.**

| 위젯 | 모양 |
|---|---|
| 보관함 상단 탭 (문장/클립/단어) | 옅은 트랙 + 흰 카드 인디케이터, 반지름 xl/lg |
| `_ViewSwitch` (내 문장/둘러보기) | 같은 계열인데 패딩 4, 반지름 15로 따로 |
| `_ViewSwitch` (내 단어/둘러보기) | 위 것의 복사본. `_SwitchButton`까지 따로 |
| `BookmarkTabs` (유형별/태그) | 흰 카드 + 테두리 + primary 틴트 인디케이터 |
| `StorageScopeTabs` (로컬/서버/클라우드) | 위와 같은 모양을 3칸으로 복사 |

**고른 방향:** **옅은 트랙 위에 선택된 칸만 표면색 카드로 떠오르는 iOS 방식**으로
모았다. `lib/core/shared/widgets/app_segmented_tabs.dart`에 `AppSegmentedTabs`를
만들었다.

iOS 표준 쪽을 고른 이유는 두 가지다. 가장 눈에 띄는 보관함 상단 탭이 이미 그 방식이고,
`primary` 틴트 인디케이터는 선택 상태가 "강조"로 읽혀서 파란 버튼과 섞인다.
트랙 위 카드는 "여기 있다"는 위치 표시로 읽혀서 고르기 컨트롤에 더 맞는다.

- 아이콘은 선택, 라벨만 쓸 수도 있다
- `locked` 칸은 옅게 그리고 자물쇠를 붙인다. 눌리기는 하므로 무엇을 보여줄지는
  `onChanged` 쪽에서 정한다 (서버 저장 "준비 중" 안내가 그대로 동작한다)
- `stacked`를 주면 아이콘을 라벨 위에 쌓는다. 보관함 상단 탭처럼 칸이 높을 때 쓴다
- 세로 여백 10에 글자 높이를 더해 **44pt 터치 영역**을 넘긴다

**외형이 바뀐다.** 라이브러리의 유형별/태그와 로컬/서버/클라우드가 흰 카드 +
파란 테두리에서 옅은 트랙 + 흰 카드로 바뀐다. 내 문장/둘러보기는 반지름이
15에서 12로, 패딩이 4로 통일된다.

**지운 것:** `bookmark_tab.dart`(`BookmarkTab`), 문장 쪽 `_SwitchItem`,
단어 쪽 `_SwitchButton`. 세 벌 모두 아무도 안 쓰게 되어 지웠다.

**아직 안 바꾼 것:** 보관함 상단 탭(문장/클립/단어)은 `TabController`로
`TabBarView`를 움직이고 있어 바꾸려면 컨트롤러 연결을 손봐야 한다. 다음에 한다.

**되돌리려면:** 이 커밋만 revert 하면 된다.

## 8. 보관함 상단 탭도 `AppSegmentedTabs`로 (세그먼트 통일 마무리)

**화면:** 보관함 상단 문장/클립/단어 탭

**왜 따로 뺐나:** 이 탭만 `TabBar`라서 `TabController`로 `TabBarView`를 움직인다.
다른 넷처럼 `value`/`onChanged`로 단순히 바꿀 수 없어 결정 7에서 미뤘다.

**고른 방향:** 컨트롤러는 그대로 두고 표시만 공용 위젯으로 바꿨다.

```dart
AnimatedBuilder(
  animation: _tabController.animation ?? _tabController,
  builder: (context, _) => AppSegmentedTabs(
    stacked: true,
    selectedIndex: (_tabController.animation?.value ?? ...).round(),
    onChanged: _tabController.animateTo,
    ...
```

**`index`가 아니라 `animation.value`를 쓴 이유:** `_handleTabChanged`가
`indexIsChanging`일 때 일찍 빠져나와서 `index`만 보면 전환 애니메이션이 끝난
뒤에야 표시가 움직인다. 쓸어 넘길 때 300ms쯤 늦게 따라오는 꼴이 된다.
애니메이션 값을 반올림해서 보면 손가락을 따라 절반 지점에서 넘어간다.

`stacked: true`로 아이콘을 라벨 위에 쌓아 기존 `TabBar` 모양을 유지했다.

**외형이 조금 바뀐다.** 기존 `TabBar`는 선택 칸에 그림자가 있었는데 공용 위젯은
그림자 없이 표면색만 쓴다. 높이도 62 고정에서 내용에 맞춰 늘어나는 방식이 된다.

이걸로 세그먼트 컨트롤 다섯 벌이 모두 하나가 됐다.

**되돌리려면:** 이 커밋만 revert 하면 된다.

## 9. 댓글 답글의 세로 안내선이 화면 끝에 붙어 있던 것

**화면:** 커뮤니티 게시글·질문·투표의 댓글

**문제:** 답글의 세로 안내선이 **화면 맨 왼쪽(x=0)에 붙어** 있었다. 글은 48pt쯤
안으로 들어가 있는데 선만 가장자리에 남아서, 들여쓰기 표시가 아니라 화면 테두리처럼
보인다. 다크 모드에서 특히 눈에 띈다.

원인은 한 줄이다.

```dart
padding: EdgeInsets.fromLTRB(isReply ? 48 : 16, 16, 16, 16),
decoration: isReply ? BoxDecoration(border: Border(left: BorderSide(..., width: 3))) : null,
```

패딩은 컨테이너 **안쪽**이고 테두리는 **바깥 끝**이다. 둘을 한 컨테이너에 주면
선과 글이 떨어진다.

**같은 코드가 네 벌이었고 값도 제각각이었다.**

| 파일 | 들여쓰기 | 선 색 |
|---|---|---|
| `board_comment_item.dart` | 52 | `tokens.disabled` |
| `vote_comments_section.dart` | 48 | `tokens.disabled` |
| `question_replies_section.dart` | 46 | `tokens.disabled` |
| `vote_view_screen.dart` | 48 | `onSurface @0.16` |

**고른 방향:** `CommentRow` 위젯 하나로 묶었다. 바깥 `Padding`이 들여쓰고
안쪽 `Container`가 선을 그린다. **선이 들여쓴 자리에 선다.**

```dart
Padding(
  padding: EdgeInsets.only(left: isReply ? replyIndent : 0),
  child: Container(
    padding: padding,
    decoration: isReply ? 왼쪽 테두리 : null,
```

들여쓰기는 `replyIndent = 32`로 모으고 안쪽 여백 16을 더해 글이 48에 선다.
기존 48 두 곳은 그대로고, 52와 46이 48로 모인다.
선 색은 네 곳 모두 `tokens.disabled`로 맞췄다.

**외형이 바뀐다.** 답글 안내선이 화면 끝에서 글 바로 왼쪽으로 옮겨온다.
이게 이번 변경의 핵심이다.

**되돌리려면:** 이 커밋만 revert 하면 된다.

## 10. 공감·스크랩 버튼을 알약으로

**화면:** 커뮤니티 게시글 보기

**문제:** 두 버튼이 **55×55 정사각형에 반지름 8, 채움 없는 테두리**였다.
앱의 나머지는 알약(필터 칩, 글쓰기 버튼)이거나 반지름 12 이상 카드라 혼자 겉돈다.
채움이 없어서 눌러야 할 것처럼 보이지도 않는다. 글 본문과 댓글 사이에 있는
이 화면의 주 동작인데 가장 약하게 그려져 있었다.

**고른 방향:** 알약으로 바꿨다.

| | 전 | 후 |
|---|---|---|
| 모양 | 55×55 정사각형 | 내용에 맞는 알약 (`AppRadius.full`) |
| 배치 | 아이콘 위 라벨 | 아이콘 옆 라벨 |
| 채움 | 투명 | `surfaceContainer`, 선택되면 강조색 12% |
| 라벨 | `bodySmall` | `bodyMedium` w700 |
| 간격 | 26 | `AppSpacing.md`(12) |

알약을 고른 이유는 이 화면에 이미 알약이 둘 있어서다. 상단의 게시판 태그
(`자유 >`)와 목록 화면의 글쓰기 버튼. 같은 언어로 맞췄다.

**터치 영역:** 아이콘 18 + 세로 여백 12×2 + 테두리 = 약 45pt로 44pt를 넘긴다.
전에도 55라 넘겼지만, 가로로 길어지면서 누르기는 더 쉬워졌다.

누를 때 살짝 작아지는 기존 애니메이션(`AnimatedScale` 0.94)은 그대로 뒀다.

**외형이 바뀐다.** 이 화면에서 가장 눈에 띄는 변경이다.

**되돌리려면:** 이 커밋만 revert 하면 된다.

## 11. 커뮤니티 하위 필터를 세그먼트 하나로 (여섯 번째 세그먼트 발견)

**화면:** 커뮤니티 게시판·질문·투표 탭의 하위 필터

**문제:** 한 화면의 세 탭이 하위 필터를 **각각 다른 모양**으로 그리고 있었다.

| 탭 | 전 |
|---|---|
| 게시판 | 채운 알약, 가로 스크롤 (`_BoardChip`) |
| 질문 | 글자 + 움직이는 밑줄 (`_QuestionTab`) |
| 투표 | **`AnimatedAlign` 인디케이터를 직접 짠 세그먼트 컨트롤** (`_VoteToggle`) |

`_VoteToggle`이 **여섯 번째 세그먼트 컨트롤**이었다. 결정 7에서 다섯 벌을 모았는데
여기 하나가 더 숨어 있었고, 하필 그때 버린 "채운 primary 인디케이터" 방식이었다.

**고른 방향:** 역할로 나눴다.

- **고정된 몇 개 중 하나 고르기** → `AppSegmentedTabs`.
  질문(채택 완료/답변 대기중/화제의 질문/오래된 질문)과
  투표(랜덤/전체/완료/만료)가 여기 해당한다. 둘 다 네 개 고정이다
- **많은 것 중에 거르기** → 가로 스크롤 칩. 게시판 말머리가 여기 해당한다.
  개수가 늘 수 있고 스크롤이 필요해서 세그먼트로 못 만든다

투표는 아이콘이 있어서 `AppSegment(icon:)`로 그대로 살렸다.

**지운 것:** `_QuestionTab`, `_VoteToggle`. 둘 다 아무도 안 쓰게 됐다.

**딸려온 변경:**

- 게시판 칩 반지름 생숫자 `18` → `AppRadius.full`. 높이 36이라 보이는 차이는 없다
- 필터 줄 높이를 바깥 `SizedBox(height: 36)`에서 안쪽으로 옮겼다. 가로 스크롤인
  게시판 칩만 높이가 필요하고, 세그먼트는 내용에 맞춰 늘어나야 하는데 36에 갇히면
  넘친다

**외형이 바뀐다.** 질문 하위 필터가 밑줄 탭에서 세그먼트로, 투표 하위 필터가
채운 파란 인디케이터에서 옅은 트랙 + 흰 카드로 바뀐다.

**되돌리려면:** 이 커밋만 revert 하면 된다.

## 12. 빈 화면을 `AppEmptyState` 하나로

**범위:** 앱 전체

**문제:** 목록이 비었을 때 보여주는 안내가 **제각각이었다.**

- 따로 만든 빈 화면 위젯 **다섯 벌**
  (`EmptyCard`, `EmptyRecentView`, `EmptyState`, `BoardCommentsEmptyState`,
  `CommunityNotificationEmptyState`)
- 그 밖에 `Center(child: Text('...없어요.'))` 한 줄짜리가 여기저기

`EmptyRecentView`와 `CommunityNotificationEmptyState`는 거의 같은 코드였다.
아이콘 48, 간격 10과 12, 제목, 간격 6, 설명. 간격 두 픽셀만 다르다.

한 줄짜리들은 아이콘도 없고 왜 비었는지도 안 알려 준다. 커뮤니티 질문·투표
탭에서는 화면 한가운데 글자 한 줄만 떠 있는데, 바로 아래 글쓰기 버튼이 있는데도
그쪽으로 이어 주지 않는다.

**고른 방향:** `lib/core/shared/widgets/app_empty_state.dart`에 하나로 모았다.

```dart
AppEmptyState(
  icon: Icons.how_to_vote_outlined,   // 없어도 된다
  title: '진행 중인 투표가 없습니다.',
  description: '새 투표를 만들면 여기에 올라와요.',  // 없어도 된다
  actionLabel: ..., onAction: ...,     // 둘 다 줄 때만 버튼이 나온다
  compact: true,                        // 목록 안에 끼울 때
)
```

아이콘 48은 다섯 벌 중 셋이 쓰던 값이라 그대로 뒀다. 간격은 `AppSpacing` 눈금으로
맞췄다.

**설명을 새로 쓴 곳:** 한 줄짜리였던 곳에는 "왜 비었는지, 어떻게 채우는지"를
한 줄 덧붙였다. 투표는 "새 투표를 만들면 여기에 올라와요", 태그는 "클립에 태그를
달면 여기에서 묶어 볼 수 있어요". 빈 화면이 막다른 길이 아니라 다음 할 일을
알려 주게 하려는 것이다.

**이번에 바꾼 곳 7:** 알림, 최근 본 클립, 투표 목록, 태그 목록, 폴더 그리드,
클립 목록, 일레븐랩스 보이스 목록.

**아직 안 바꾼 것:** `EmptyCard`(홈 카드 안에 들어가는 꼴), 자막 `EmptyState`
(98줄짜리 카드형), `BoardCommentsEmptyState`(고정 여백 130과 안내 줄이 따로 있음).
셋 다 구조가 달라서 그대로 옮기면 모양이 크게 바뀐다. 따로 본다.

**외형이 바뀐다.** 한 줄짜리였던 다섯 곳에 아이콘과 설명이 생긴다.

**되돌리려면:** 이 커밋만 revert 하면 된다.
